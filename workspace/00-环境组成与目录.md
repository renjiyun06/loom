# 环境组成与目录

## 组成

织境以 Glamorous Toolkit 的活对象环境承载程序，通过本机 Codex App Server 调用模型。当前使用官方 Glamorous Toolkit v1.1.699 Windows x86_64 便携版、随环境携带的 Codex 和 Node；具体文件来源、哈希与版本依据在 `../config/runtime-manifest.json`，运行配置在 `../config/runtime.json`。配置和实际运行对象可能更新，目录名不证明某个能力已经加载。

| 部分 | 当前职责 |
| --- | --- |
| Glamorous Toolkit | 保存业务对象、方法、执行进程与原生界面，在程序调用点请求 Codex。 |
| Codex App Server | 维护模型会话、运行模型轮次，并将工具回调交给桥接程序。 |
| Node 桥接 | 连接两者，处理请求、结果、会话绑定、检查点和原生保存退出。 |
| Windows 监管程序 | 将本地执行进程及普通子进程纳入同一 Job，处理联动停止。 |

这套环境可独立启动，不依赖 Mira 后台。Mira 中的工程登记是管理记录，不是本环境的模型调用或执行机制。

## 入口与工作位置

`D:\Loom\workspace` 是 Loom 启动或恢复底层 Codex 会话时传入的统一 `cwd`。主会话和其他命名会话由此加载同一份 AGENTS.md 和按需文档。实际业务工作按以下步骤定位。

1. 根据本次请求确定目标，是活对象、已有程序、文件还是其他工程。
2. 读取相应对象或确认文件位置，核对已有改动和当前状态。
3. 在实际目标所在位置工作。新任务需要磁盘目录时先明确位置，不把产物留在入口目录。

维护织境自身的运行实现时使用本环境的 `src`；处理其他业务时不要因此把 `src` 当成通用业务目录。

| 根目录下的位置 | 职责 |
| --- | --- |
| `workspace` | 环境说明入口和编号文档。 |
| `src/runtime` | 运行时装载、客户端、对话程序、检查点与原生生命周期适配的初始源码。 |
| `src/bridge` | App Server 协议、本机通信、独立会话绑定和保存恢复。 |
| `src/supervisor` | Windows Job 监管程序源码及构建入口。 |
| `src/documentation` | 文档目录同步和校验工具。 |
| `src/audio`、`runtime/audio`、`runtime/media` | 本地录音与播放、讯飞转录源码及随环境携带的执行程序。 |
| `runtime` | 本环境携带的 Glamorous Toolkit、Codex、Node、监管程序及依赖。 |
| `config` | 运行路径、模式、运行文件来源等配置。 |
| `state/runtime` | 初始镜像、活动副本、执行检查点及恢复指针。 |
| `state/bridge` | 独立会话绑定、显式切换和模型调用回执。 |
| `state/conversation` | 当前对话程序的持久输入与回答。 |
| `state/audio` | 原音、派生音频、转录订单和结果。 |
| `state/codex` | 本环境专用 CODEX_HOME，包括配置、登录和原生会话数据。 |
| `ipc`、`logs` | 临时通信与实际执行记录。 |
| `backups`、`tests/results` | 备份与验证依据。 |

运行中的 `ExperimentRoot` 和 `BridgeIPC` 全局对象给出 Glamorous Toolkit 侧实际根目录及通信位置。当前活动镜像位置可查 `Smalltalk imageFile fullName`；启动活动副本与后续另存快照的路径可能不同，不要据目录名猜测当前加载的 image。

## 版本管理

Git 仓库位于 Loom 根目录，记录源码、启动脚本、测试源码、文档和源码依赖的静态资源。Loom 的说明和专题文档在 `workspace` 下维护。所有 Git 跟踪内容均由运行时身份为 `main` 的 Loom 会话维护。主会话在活镜像中修改系统代码后，需要同步到对应的磁盘源码，Git 才能记录改动。

镜像、会话、运行程序、下载包、本机配置与凭据、日志及测试产物仍放在各自的本机目录。Git 历史用于追踪源码和文档，运行现场由 [保存恢复与生命周期](03-保存恢复与生命周期.md) 所述的机制保存。

### 提交时机与范围

主会话每完成一项改动，应先核对差异，再按影响范围验证，验证通过后提交。文档改动检查目录与链接，代码改动验证实际受影响的行为。一个提交对应一项可独立说明的改动，只暂存与该项改动相关的文件。提交后通过 `git status` 和 `git log -1` 核对结果。

### 提交消息

标题统一采用 `类型(范围): 简短说明`。类型和范围用小写英文，说明用一句中文交代具体改动。范围指主要改动区域，例如 `workspace`、`bridge`、`runtime`。需要说明原因、迁移或验证时，在标题后空一行，再写正文。

| 类型 | 用途 |
| --- | --- |
| `feat` | 新能力或行为 |
| `fix` | 修复问题 |
| `refactor` | 调整代码结构 |
| `docs` | 修改文档 |
| `test` | 修改测试或验证脚本 |
| `chore` | 构建、依赖或仓库维护 |

示例为 `docs(workspace): 约定 Loom 的 Git 提交流程` 和 `fix(bridge): 恢复已保存的会话绑定`。

## 启动与界面

桌面 **织境** 快捷方式只启动或唤出当前工程的 Glamorous Toolkit 本身，不额外弹出对话窗口。已保存的对话标签在主窗口内恢复；关闭过的标签不会被快捷方式强制打开，可点击右上角聊天图标重开。快捷方式经 `open-loom.vbs`、`open-loom.ps1` 进入同一监管启动流程，启动辅助窗口隐藏。后台已运行但主窗口关闭时，会重新启动图形循环并打开主界面；窗口最小化时恢复显示。实际打开逻辑在 `src/bridge/open-environment.mjs`，不依赖缓存的进程主窗口句柄。

```powershell
& D:\Loom\start.ps1 -Gui
& D:\Loom\start.ps1 -Headless
& D:\Loom\stop.ps1
```

不带模式参数沿用上次模式。切换模式会先保存并停止旧实例，再恢复到新模式。关闭对话标签只关闭呈现，消息处理与当前会话继续保留；退出 Glamorous Toolkit 的原生流程见 [保存恢复与生命周期](03-保存恢复与生命周期.md)。

当前官方便携版位于 `runtime/gtoolkit`，下载 ZIP 保留在 `downloads`。官方版本与校验和在 `config/gtoolkit-release.json`；工具包镜像版本通过 `GtImage version asString` 核对，启动器或 VM 自身的组件版本与它不同。GT 的上游依赖文件保留厂商原名，不自行改名。
