# 运行环境的观察与演进

## 从活环境开始

通过当前实际提供的 运行时求值工具（以当前提供的工具名为准） 执行 Smalltalk。它访问的是发起本次模型调用的同一个 image，而不是一个另建的解释器。先返回足够定位问题的对象信息，再深入读取需要的字段、源码与上下文。

```smalltalk
Smalltalk globals keys asArray
```

```smalltalk
LoomConversation state
```

```smalltalk
(LMConversation >> #run) sourceCode
```

```smalltalk
LMConversation allInstVarNames
```

```smalltalk
(LoomConversation instVarNamed: 'worker') suspendedContext printString
```

工具回调通过 JSON 返回结果。对象、进程和方法本身通常不能直接序列化，应返回标识、类名、选定字段或源码；必要时将集合转为数组。不要为了序列化方便而修改业务对象。

## 理解调用位置

当前 `LMCodexClient` 在独立业务 Process 中等待模型，通信邮箱继续运行以响应工具。运行时求值工具（以当前提供的工具名为准） 本身由邮箱执行：需要等待检查点或其他业务处理时，使用独立 Process，避免占住邮箱。

对象调用中，`loomCaller` 是这次调用的业务栈帧，`loomMessage` 是发出的原始消息。从这里读源码、定位表达式、检查实际对象，并沿调用栈追溯，根据业务代码判断返回值的用途。

```smalltalk
loomCaller method sourceCode
```

```smalltalk
{ loomMessage selector asString. loomMessage arguments size. loomCaller sender printString }
```

`loomCaller sourceNodeExecuted` 可用于定位当前执行的源码节点。查看实参时，可直接读取 `loomMessage arguments` 中有用的对象字段，再返回适于 JSON 回显的值。绑定、参数和对象返回入口见 [工具技能与能力发现](04-工具技能与能力发现.md)。

```smalltalk
[ LMExecution checkpoint ] fork
```

不要在这个回调里同步执行同一 `LoomCodex ask:`，否则正在等待工具结果的模型调用与新的模型调用会相互等待。当前显式调用入口并不意味着已经实现所有任意消息拦截语法；新增调用形式时先检查实际机制。

## 局部演进

先确定目标行为及相关对象，再读取当前方法、调用者、状态与执行位置。按任务进行局部替换，验证后续调用是否使用新实现，同时检查原有对象是否仍满足新方法的假设。

替换方法后，后续的方法发送可以使用新方法；已经进入原方法的调用栈可能继续执行旧方法。改变类的字段、进程循环或通信边界时，还需要考虑存量实例和正在等待的进程。不要把“编译成功”当成整条业务路径已经生效。

本环境支持演进承载模型调用的程序。对话方式、上下文准备、检索、消息存储和界面都可按用户目标调整，不应因为文档描述了当前实现就禁止更换。

## 活镜像与初始源码

`src/runtime/conversation.st` 是初始安装实现。当前启动仅在镜像缺少对话对象时装载它，避免每次重启覆盖运行时演进。活方法可能比该文件更新。

修改时区分三件事：当前运行的实现、已提交检查点中的实现、磁盘上用于初始装载或重建的源码。按本次目标决定需要同步哪些位置，并记录差异。不要用重新运行整个初始安装脚本代替局部修改。

修改后选取真实行为检查，再通过统一保存流程持久化。保存细节见 [保存恢复与生命周期](03-保存恢复与生命周期.md)，验证入口见 [验证与故障排查](05-验证与故障排查.md)。

## 用户查看环境

GT 的 Coder 查看类与方法，Inspector 查看活对象，Playground 执行表达式，Debugger 查看执行上下文。在 Playground 执行 `LoomConversation inspect` 可打开对话实例的 Inspector。打开对话标签的方法见 [对话程序与调用机制](02-对话程序与调用机制.md)。
