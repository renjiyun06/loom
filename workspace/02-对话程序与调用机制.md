# 对话程序与调用机制

## 当前程序

| 对象或类 | 职责 |
| --- | --- |
| `LoomConversation` | 当前正在运行的对话对象。 |
| `LMConversation` | 接收输入、等待、调用模型并保存回答。 |
| `LMConversationUI` | 采用 GT Bloc/Brick 的原生对话标签。 |
| `LMVoice` | 本地录音、导入、播放及转录操作。 |
| `LoomCodex`、`LMCodexClient` | GT 业务程序调用模型的入口，沿用持久线程和调用回执。 |

对话类位于 `Loom-Conversation` 包。客户端、对象调用、会话管理和 GT 内的 App Server 连接都位于 `Loom-Codex` 包。

GT 里的程序决定入口、运行分支和结果去向。聊天是当前程序采用的交互方式，用户输入、最终回复和业务状态由 Loom 管理。同一份 Loom 历史可以先后对应多条底层 Codex 会话。

## 对话循环

1. `submit:` 保存用户输入并唤醒等待的程序。
2. `run` 寻找尚未产生回答的输入，没有输入时等待 Semaphore。
3. 语音输入等到讯飞转录出文字后才就绪。`answer:` 用 `LoomCodex session: #main` 选中会话，并在这条底层 Codex 会话中先纠正转录，保存纠正结果。
4. `preparePrompt:` 从就绪消息准备本次上下文，录音消息保留 `kind: audio` 标记并使用纠正后的文字。`replyTo:usingContext:` 把消息和上下文传给同一条底层会话。完成后 `process:` 保存返回的文本或错误，再回到循环。

等待新消息发生在 Glamorous Toolkit 中，不通过持续调用模型维持循环。关闭对话标签不终止这个程序。

消息和回复保存在 `state/conversation/conversation.sqlite`，按消息 ID 对应并按发送序号读取。首次升级时，存储层可在一个事务中导入旧 `inputs` 和 `replies` 下的 JSON。当前环境已完成迁移并清理旧目录。界面读取 SQLite，对话历史和模型线程上下文各自持久化。

GT 应用层通过 Windows SQLite 初始化对话存储，聊天入口独立报告启动或迁移错误。修复存储或修改业务源码后，可在 GT 中执行 `LoomApplications reload` 热装载。已经进入旧方法的调用可能继续用旧逻辑，直到返回。

点输入栏的回形针可选一个或多个本地文件。待发送的文件在输入框内顶部排列成一行，可逐个移除。长文件名截短时优先保留扩展名，悬停可看全名。点「+N」可展开其余文件。正文可以留空。发送时复制原文件到 `state/conversation/attachments/<附件ID>/`。消息只携带按添加顺序排列的 `attachmentIds`。数据库的附件记录保存显示名及相对于 `state/conversation` 的路径。已发送的附件在正文下方以右对齐的卡片显示。点击卡片打开附件。文件名在窄窗口可以换成两行，过长时在中间省略，悬停可查看完整名称。原文件移走后可以通过已保存的副本打开，副本缺失时卡片会提示。

对象调用沿用 `replyTo:usingContext:`。调用期间从 `loomMessage` 取得 `attachmentIds`，用 `LoomConversation attachment: id` 查附件记录，再通过 `LoomConversation fileForAttachment: attachment` 得到本地文件。发送给 Codex 的模型轮次沿用原调用协议。GT 消息存储在 `src/runtime/conversation-db.st`。

## 模型调用与工具返回

`LMCodexClient` 将请求写入 `ipc/codex-requests`。GT 的请求进程直接通过 stdio JSON-RPC 调用 Codex App Server，把轮次回执写入 `ipc/codex-responses`。`ask:` 返回文本。开始连接等单个协议请求有等待上限。正常运行时，模型轮次等待完成或明确的连接故障。

```smalltalk
LoomCodex lastResponse
```

回执可包含 request ID、thread ID、turn ID、模型、时间和错误。当前程序串行处理模型请求。App Server 通过同一条 JSON-RPC 连接发出 `runtime_eval` 调用，GT 在独立的 Process 中求值并沿该连接回送结果。模型等待工具时仍在同一轮调用中。本机命令另用 `ipc/mailbox` 和 `ipc/results`。

不要在这个回调内递归调用同一个模型客户端。需要独立业务进程的场景和反射示例见 [运行环境的观察与演进](01-运行环境的观察与演进.md)。

### 通过 Smalltalk 消息调用 Codex

在独立的 GT Process 中，程序用 `LoomCodex session:` 选中命名会话，再向它发送一个未定义的 Smalltalk 消息。Loom 在 GT 中保留方法名、任意个数的活对象实参和调用方上下文，本轮初始文本只有「Loom 调用了你。」。Codex 按 AGENTS.md 从运行时工具查阅现场。

```smalltalk
"优先选原始资料，按与问题的相关程度排序。"
selected := (LoomCodex session: #sourceResearch) selectSources: sources for: researchQuestion.
^ selected collect: #url
```

这次调用期间，`runtime_eval` 提供业务调用帧 `loomCaller` 和原始消息 `loomMessage`，由 Codex 通过 Smalltalk 反射查阅调用现场、实参和下游代码。用 `loomReturn value: anObject` 提交一个已有对象或新构造的对象，`nil` 也可以显式提交。工具确认前会保存含结果的检查点。轮次成功后，原程序拿到这个对象并从调用处继续执行。轮次失败、中断或没有提交对象都会在原调用点给出错误。绑定和工具参数见 [工具技能与能力发现](04-工具技能与能力发现.md)。

业务方法和对象类型由调用方表达。对话程序使用这套机制，并约定结果是一条可直接展示的 Smalltalk String。

## 原生界面

GT 主窗口右上角聊天图标打开或选中「织境对话」标签。入口沿用 GT 的 `emphasizedChat`，标签本身以同一个图标表示，操作区保留关闭按钮。GT 原有聊天入口不再展示，避免两个聊天入口并列。桌面快捷方式本身只负责启动或唤出整个环境。

在 GT 主界面顶部菜单打开 Playground，输入并执行：

```smalltalk
LoomConversation open
```

「织境对话」直接从消息与活动区开始。左侧按消息展示 Markdown 与流式回复，正文 14、活动 13、辅助文字 12。复制和 Markdown 源码操作不执行内容。右侧将进度、工具调用及异常按原顺序呈现在同一个列表，点开条目可查看参数与结果，展开状态会保留。宽屏时把鼠标放到中间分隔线上，可以左右拖动来调整活动栏宽度。输入框按 Enter 发送、Shift+Enter 换行，小键盘 Enter 同样适用。空白消息不发送，长按 Enter 不重复发送。快捷键提示在输入框底部，与输入占位文字左对齐。回复行显示「正在处理」，收到正文后流式显示回复。中文使用 Microsoft YaHei UI。发送按钮旁的麦克风可展开录音条。录音发出后，同一条消息显示可播放的原音，并依次显示「正在转录」「正在纠正」和纠正后的文字。纠正完成后自动进入正式处理。详见 [长录音消息与转录](07-长录音消息与转录.md)。

在 Inspector 底部执行 `self state` 或 `self records` 可检查对话状态和记录。也可执行 `D:\Loom\runtime\node\node.exe D:\Loom\src\tools\open-conversation.mjs` 打开标签。重复打开选中同一个标签；关闭后重开保留历史与未发送草稿。草稿随镜像检查点保存，正常保存重启可恢复；它不是已经提交的持久消息，异常退出只能恢复最后成功检查点中的草稿。当前没有网页对话入口。

`LoomConversationWindow` 是沿用的界面控制对象名，不代表另一个操作系统窗口。`presentationSpace` 是供 GT 原生标签承载的虚拟 `BlSpace`，`hostWorld` 指向实际主窗口。切到其他标签时刷新继续；关闭标签后刷新进程结束，重开重新启动。启动只在界面功能版本落后时升级界面，不重建对话模型或切换 Codex 会话。

活动面板顶栏的齿轮打开运行设置。模型与思考强度用下拉菜单选择，Fast 通过开关控制。默认是 GPT-6.2-Sol、High、Fast 开启，保存在 `config/codex.json`。界面使用本机 Codex 模型目录显示可用选项，保存后从下一次调用生效。顶栏的会话切换按钮切换默认对话会话的底层 Codex 会话。Loom 的历史继续按原来的记录追加。

## 流式回复与活动历史

Loom 将 Codex 工具、进度、流式回复项和手动会话切换统一写入 `state/sessions/sessions.sqlite` 的 `loom_activities` 表。每条活动按首次写入的顺序展示，同一调用与条目的后续事件更新原记录。

GT 主窗口右上角的「运行活动」图标打开独立标签。左栏可选「全部会话」或某一条已登记的 Loom 会话，右侧按时间显示活动及其会话标识。活动条目可展开查看工具参数、结果和状态。标签初次加载最近 100 条活动，「加载更早」从同一张表读取历史并保留阅读位置。对话右侧按 `main` 的范围读取活动。

旧版本的活动已随迁移写入 SQLite。现行 GT 活动记录由 App Server 的协议事件产生，历史活动从 SQLite 读取。

GT 按会话、轮次和条目记录 App Server 事件。两个活动视图在后台从 SQLite 分页读取摘要，并按变更版本读取更新的条目。已加载的范围和翻阅位置由各个视图维护。展开条目时，在后台按记录读取并格式化完整内容。图形队列只应用列表和详情的更新。当轮流式正文独立读取，完成后的回复正文由对话记录承载。

活动条目使用统一的 Lucide 图标和紧凑的展开区域。工具条目显示名称、状态和耗时，参数与结果在条目内按需展开。阶段预览按栏宽显示省略号，展开读取全文。活动列表为空时显示空态提示。思考内容使用服务提供的摘要，结构化凭据字段在投影中隐藏。

关闭标签停止界面阅读进程，重新打开后从持久活动表恢复展示。镜像恢复沿用原 Codex 线程。活动存储、查询与视图分别由 `src/runtime/codex-activity.st`、`codex-controls.st` 和 `activity-timeline.st` 承载。

## Markdown 与原生条目

LMChatStyle 和 LMMarkdownView 提供聊天专用只读渲染，支持标题、段落、列表、引用、表格、粗体、斜体、链接、行内代码及代码块。未完成的代码围栏可持续显示，代码块只展示和复制，不编译、求值或接入交互式代码编辑能力。点击明确的链接才打开浏览器或本地文件。

LMConversationMessageView 和 LMConversationActivityView 是可复用的列表条目。用户消息通过右侧气泡区分，气泡下只显示发送时间。已完成的回复直接呈现正文，处理中或未完成的回复显示对应状态。消息与活动按稳定 ID 对齐，未改变的条目不重新绑定。流式消息仅替换变化的 Markdown 块。工具展开及详情标签在行复用后保留。图形线程只应用投影，不读取整份事件日志。用户离开正文底部后，新消息由输入框上方的「有新内容 · 回到最新」提示。点提示或滚回底部恢复跟随。活动列表在底部自动跟随新事件，向上查看时暂停跟随，滚回底部恢复。

渲染后的同一条回复支持跨段落拖选和复制。点按回复下方的复制按钮会复制整条回复，成功时图标短暂变为对勾。

正文和输入区共用左右边距，使用居中的 1080 宽阅读容器，视口达到 1600 时上限为 1160。短用户消息按字形宽度收缩并显示本地时间。正文原生行盒约 25 高，输入区按内容在 62 至 150 之间增长。代码块和宽表格在块内横向滚动。视口不超过 800 时仅显示对话正文，更宽时活动栏自动并排显示。

`src/runtime/conversation-components.st` 提供可直接在 Smalltalk 中调用的 `LMChatStyle`、`LMMarkdownView` 与活动条目。按钮、文字、居中阅读边距、按字形测量的省略号和块内横滚都集中在 `LMChatStyle`。`src/runtime/conversation-ui.st` 里的 `build` 和 `updateResponsiveGeometry` 展示如何用 Brick 的纵横布局组合输入区和内容，再用 Bloc 的 `BlFrameLayout` 按视口宽度安排侧栏。列表复用时，展开状态按业务 ID 保存。

例如，在 GT Playground 求值后 Inspect 返回的元素，就能在其他页面里复用同一种只读 Markdown 排版：

```smalltalk
LMMarkdownView new text: '## 检查结果', String lf, String lf, '本轮已完成。'; yourself
```

新增页面时，按页面需求选用 Brick 或 Bloc 组件，并在 GT 中核对字号、行高、留白、布局切换和交互状态。`tests/native-conversation-prototype.st` 使用独立的原生控件验证布局切换、横滚、空状态和消息跟随。

### Loom 图标库

新定制页面优先使用 Lucide。`assets/icons/lucide/icons` 收录固定版本的官方 `lucide-static` SVG，导入时将紧凑路径转为 GT 可读的等效写法。版本、来源、包摘要、路径处理脚本和许可证记录在上一级目录。原生页面通过 `LMIcons` 按文件名取得图标，默认大小为 16，颜色为中性灰。读取和渲染都在本地。

```smalltalk
LMIcons iconNamed: 'search'.
LMIcons iconNamed: 'copy' size: 16 color: (Color gray: 0.45).
LMChatStyle iconElementButton: (LMIcons iconNamed: 'code-xml')
 title: '查看 Markdown 源码'
 action: [ "打开当前页面的源码视图" ]
```

SVG 的轮廓由 Bloc 原生绘制，同一图标可以在不同按钮上使用不同大小和颜色。会话回复的复制和源码按钮已采用这套图标。HTML 页面可按相同名称使用对应的 SVG 文件。升级图标包后运行 `tests/native-lucide-icons.st`，核对整套图标都可从原生入口加载。

## Loom 会话管理

GT 主窗口右上角的会话管理图标打开独立的「会话管理」标签。系统会话有持久的唯一标识，可登记命名会话并查看它的运行状态、当前底层 Codex 会话及历次接续。`main` 排在首位，也是当前原生对话程序选择的会话。任何会话都可以通过程序提供的入口与使用者沟通。修改决定 Loom 系统行为的代码由 `main` 承担。旧版 `conversation` 升级时原地改名为 `main`，保留 `default` 客户端绑定、底层 Codex 会话和历史活动。

```smalltalk
result := (LoomCodex session: #failureRecovery) handle: failure.
LoomSessions list.
LoomSessions show: #failureRecovery.
```

`session:` 接受字符串或 Symbol，首次使用登记该标识，后续返回同一个 GT 客户端。有效标识由字母或数字开头，可含字母、数字、点、下划线和连字符，最多 96 个字符。命名会话各有独立的 Codex 绑定，GT 按轮次串行执行。对象调用在业务 Process 中进行。查询通过独立的本机管理通道进行，模型轮次运行时仍可使用。

空闲时可切换它的底层 Codex 会话，下一次调用建立新的底层会话。Loom 标识、历史和其他会话保留。异常恢复与回执规则见 [保存恢复与生命周期](03-保存恢复与生命周期.md)。

本机也可运行 [manage-sessions.mjs](../src/tools/manage-sessions.mjs) 的 `list`、`show <id>`、`register <id>` 和 `rotate <id>`。
