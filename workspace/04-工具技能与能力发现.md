# 工具技能与能力发现

## 以当前装载为准

技能告诉模型怎样完成工作，执行工具提供真正的读取、计算或操作能力。有技能文件、缓存包或目录，不等于对应的服务、工具或依赖已可用。

模型调用时先查看当前提供的工具及参数。运行时求值工具（以当前提供的工具名为准） 是本环境为访问同一活镜像接入的动态工具；其他内建或账号侧工具以实际会话为准。不要从其他桌面会话拥有的能力，推断本环境已经拥有相同能力。

## `runtime_eval`

传入一个 JSON 对象，唯一字段 `code` 是 Smalltalk 源码字符串。源码在发起调用的 GT 活镜像内求值，可以观察对象、方法和执行上下文，也可在任务授权范围内修改它们。工具回显为 `{ok:true,value:…}` 或 `{ok:false,error:…}`，复杂的 GT 对象可先转换为可序列化的字段或摘要。

通过 Smalltalk 对象调用触发时，`code` 内可直接使用以下运行时绑定。

- `loomSessionId` 是 GT 按本次调用的客户端查出的 Loom 会话标识，例如 `'main'`。没有命名会话绑定时为 `nil`。先核对它再承接 Loom 自身的维护任务。
- `loomCaller` 是发起调用的原始 Smalltalk `Context`，可用原生反射查看方法、源码和上层栈帧。
- `loomMessage` 是原始 Smalltalk `Message`，可读取 `selector` 和 `arguments`。实参是活镜像内的对象。
- `loomReturn` 是提交结果的一参数块。调用 `loomReturn value: anObject` 将活对象交回业务程序，返回 `nil` 时同样显式提交。`code` 的结果单独用作 JSON 工具回显。

恢复调用的 `loomMessage selector` 为 `#recover:after:`，`loomCaller` 指向当次恢复调用。`loomMessage arguments first` 是原业务调用，可用其 `message` 和 `caller` 找到原始入口和实参。第二个实参是上一轮回执，可用其中的 `id` 读取该轮活动。查询用法见 [对话程序与调用机制](02-对话程序与调用机制.md#通过-smalltalk-消息调用-codex)。

Codex App Server 通过 stdio JSON-RPC 调用该工具，GT 在独立的 Process 中求值并把 JSON 回显写回管道。对象调用提交结果时会保存检查点。模型轮次在等待工具返回期间仍占用当前客户端，回调内避免同步发起另一轮模型调用。本机脚本另可通过文件邮箱执行独立的 Smalltalk 命令。求值和修改示例见 [运行环境的观察与演进](01-运行环境的观察与演进.md)。

## 专用配置与参考

- Codex 的加载入口 `cwd` 为 `D:\Loom\workspace`，不代表业务工作目录。
- App Server 沿用 Codex 自己的 `CODEX_HOME` 解析规则，Windows 默认使用 `%USERPROFILE%\.codex`。GT 用 App Server 的 `model/list` 获取模型选项，Loom 自己的模型、推理强度和服务档位保存于 `config/codex.json`。
- GT 的 Codex 客户端为新建和恢复的会话设置 `danger-full-access` 与 `approvalPolicy: 'never'`。普通 shell 使用 Loom 进程的 Windows 账户权限读写文件和访问网络。系统代码的维护职责按入口文档中的主会话约定执行。
- `runtime` 中保存实际运行程序，`config/runtime-manifest.json` 记录来源与哈希。查看全局安装只可作为对照，不能当成当前执行器的实际配置。

排查 App Server 协议时，按 Loom 所带的 Codex 版本查阅对应的方法和字段定义。

可用的发现入口包括 `skills/list`、`mcpServerStatus/list`、`config/read` 等。它们是 App Server 协议方法，不是保证已经暴露给模型的同名工具；通过实际接入层使用并核对返回。技能列表可能缓存，需要时按同版定义请求刷新。账号侧可能自动提供服务，不能只因配置文件没有显式 MCP 条目就断言没有 MCP 工具。

## 当前边界

Computer Use 按用户当前要求暂不接入。不要把读取到的技能文档或缓存解释为已经能够截图、点击、输入或控制桌面。后续若获准接入，需要同时确认执行工具、图像回传、依赖和生命周期，而不只是复制一份技能文档。

当前对话程序提供 Glamorous Toolkit 原生界面。GT 的 Codex 客户端会对未实现的交互请求返回协议错误。

## 能力演进

根据当前目标选择需要的能力，核对运行条件和实际输出。新的本地工具进程应延续同一受管生命周期；新能力的入口、依赖、用法与限制应补入相应现行文档，再同步目录简介。工具调用和故障核对见 [验证与故障排查](05-验证与故障排查.md)。
