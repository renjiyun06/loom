# 验证与故障排查

## 先选能说明问题的检查

先明确改动要产生的行为和需要避免的偏差。读取实际对象或回执，选择足以核实本次改动的检查；通过后不要无理由重复耗时、调用模型或强制重启的测试。

共享运行时的检查逐个执行。部分脚本会真的强杀进程、冻结 Glamorous Toolkit、退出界面、恢复镜像或调用付费模型，不是普通只读检查；运行前核对脚本内容、当前工作和保存状态。结果文件是当次验证依据，不自动证明之后的版本仍然通过。

| 脚本（根目录下） | 覆盖范围 |
| --- | --- |
| `src/documentation/catalogue.mjs --check` | 文档元数据、编号与标识、目录一致和现行文档内部链接；不修改文件。 |
| `tests/desktop/check-reopen.mjs` | 主动关闭空的 GT 主界面并保留后台，确认 UI 循环停止后通过真实桌面快捷方式恢复；需明确运行，不用于有未保存编辑的桌面。 |
| `tests/launcher-encoding.test.mjs` | 使用桌面入口同版 Windows PowerShell 5.1，核对 UTF-8 中文配置与状态的实际读取，防止重复启动后乱码。 |
| `tests/loom-runtime.test.mjs` | 官方下载包哈希、活镜像版本、原会话和对象、音频与凭据就绪。需启动环境。 |
| `tests/gt-codex-contract.st` | GT 内的持久会话、活动导入与分页、调用回执和模型设置。由隔离测试执行。 |
| `tests/checkpoint-storage.test.mjs` | 最新一代保留、损坏或不完整恢复文件、活动文件保护、路径和目录链接边界、旧指针兼容。使用隔离目录。 |
| `tests/desktop/checkpoint-preservation.mjs` | 正常保存重启前后比较原线程、消息、草稿及全部 LM 类方法的摘要。结果在 `tests/results/checkpoint-optimization`，不输出草稿正文，不调用模型。 |
| `tests/gt-voice-recovery.st` | GT 音频队列恢复、已有订单续查、上传未知不重传、词时间戳、合成音频导入和 Windows 子进程通信。由隔离测试调用。 |
| `tests/desktop/check-application-isolation.mjs` | 临时受管 Loom 的冷启动、热装载、附件、音频恢复和保存重启。重启后检查工作副本的源码、桌面标签和退出提示。`--mock-codex` 另验对象回调、取消、活动、会话续接及重启后的界面回显。 |
| `tests/desktop/ime-native.c`、`ime-ffi.st` | 隔离验证 Windows 输入法候选框坐标和 GT 事件线程 FFI。不发送模型消息。 |
| `tests/desktop/ime-diagnostics.st` | 在主窗口新建独立输入测试标签，保留原对话输入；仅用于主动桌面排查，结束后移除测试标签及临时全局对象。 |

```powershell
& D:\Loom\runtime\node\node.exe D:\Loom\src\documentation\catalogue.mjs --check
```

当前运行检查使用 `tests/loom-runtime.test.mjs`，核对官方包、活环境、持久会话绑定与本地音频。会话事务与语音恢复由对应单元测试检查；桌面恢复结果见 `tests/results/desktop-reopen.json`。

GT 在当前 Windows 机器上默认 ANGLE 路径显示空白，`src/runtime/desktop-compat.st` 将其切换到 GT 自带的 Direct3D 路径。官方 ZIP 保持原样。对照时不要把启动器/VM 组件版本当成 `GtImage version`。

## Windows 中文输入

`src/runtime/windows-ime.st` 处理 Winit30 与 GT 编辑器之间的输入法适配，启动时由 GT 应用层装载。Windows 的 `VK_PROCESSKEY` 由输入法处理，不能作为普通 Unknown 按键保留在 GT 的按键缓冲区：其抬起事件可能对应另一个实际按键，残留状态会阻断退格等快捷键。

候选框位置来自当前获得焦点的编辑器内实际 `BrCursorElement` 的 `boundsInWindow`。这个坐标已包含标签页、父容器、滚动及窗口缩放；不能用虚拟标签空间的原点或再次乘 DPI。图形循环在光标位置变化时更新，输入法组词开始时强制同步一次。`LoomImeLastError` 保存适配错误，`space root userData` 中的 `loomImeAnchor` 用于核对已成功传递的位置。

本机辅助库 `runtime/windows-ime/LoomWindowsIme.dll` 在窗口事件线程上设置 Windows 的组合窗口和候选区域。源码及构建入口为 `src/windows-ime/WindowsIme.c`、`build.ps1`，使用已安装的 Visual C++ 工具链与 Windows SDK：

```powershell
& D:\Loom\src\windows-ime\build.ps1
```

辅助库已加载时不能覆盖 DLL，应先正常保存并停止环境。GT v1.1.699 的事件线程 FFI 不支持 32 位整数返回值，直接用 Win32 `BOOL` 返回会导致 VM panic；辅助库将结果转换为支持的 `uint64`，并在本机代码中成对获取、释放 IME 上下文。新增 FFI 接口先用独立进程验证，再接入活环境，不能直接在用户的编辑现场试验未核验的签名。

隔离验证包括 `ime-native.c` 的两个实际 Windows IME 坐标读回，以及以官方初始镜像运行 `ime-ffi.st` 的无效窗口处理与返回值转换。桌面还需实际输入中文：组词退格不能改正文、中文提交后退格可删除、候选框跟随光标，随后核对英文和原会话。2026-11-21 在搜狗、150% 缩放下完成该验证，依据在 `tests/results/windows-ime.json`。异常退出仍只恢复最后成功提交的镜像检查点，不保证恢复其后的未保存草稿。

## 查实际记录

检查点空间应为最新一代封存 image/changes 加固定工作副本，不能随调用次数无限累积。当前保留规则见 03 文档。修改保存或保留逻辑时，先跑隔离存储边界测试，再实际连续保存、重启，核对活对象和方法摘要未变化、最新双文件摘要有效、目录只有一代。不能只证明文件变少而省略恢复检查。`logs/checkpoint-retention.json` 记录保留代次、删除路径及失败项。

| 位置 | 用途 |
| --- | --- |
| `ipc/bridge-ready.json` | 直连就绪状态、进程 ID 和镜像位置。直连就绪时 `pid` 与 `enginePid` 都指向 GT，`supervisorPid` 和 `codexPid` 分别指向监管程序和 App Server。核对进程存活和父子关系可确认记录对应当前实例。 |
| `LoomApplications statuses` | GT 中对话、录音和桌面的就绪或故障。应用装载入口异常可查全局 `LoomApplicationLoadError`。 |
| `logs/supervisor.log` | 冷启动、检查点封存和整组故障原因。 |
| `logs/runtime.stderr.log`、`logs/codex.stderr.log` | Glamorous Toolkit 和 Codex 的错误。 |
| `logs/commands`、`logs/interrupted-commands` | 本机文件邮箱的代码及重启时隔离的旧命令。 |
| `logs/codex-events` | 旧版的模型事件归档。实时活动和调用回执可查 `state/bridge/sessions.sqlite`。 |
| `ipc/checkpoint-results`、`ipc/native-results` | 检查点和原生保存退出回执。 |
| `state/runtime/current-image.json` | 当前已提交的恢复依据。 |
| `logs/launcher-error.log` | 桌面启动入口错误。 |
| `tests/results` | 已执行检查的结果与证据。 |

如果启动提示提到旧服务的 `logs/service.stderr.log`，直连启动错误查 `ipc/bridge-ready.json` 和 `logs/runtime.stderr.log`，Codex App Server 错误查 `logs/codex.stderr.log`。

工具超时后先核对实际请求和返回文件，确认是否已执行，再决定下一步。不要为了重试而重复创建线程、重复执行不确定的外部操作或重放旧通信命令。

## Windows 桌面启动的编码

`open-loom.vbs` 调用 Windows 自带的 PowerShell 5.1。其默认文件编码不能用于读取本环境的 UTF-8 JSON；`start.ps1`、`open-loom.ps1` 和 `stop.ps1` 中读取配置及状态时必须明确 `-Encoding UTF8`，写配置继续使用 UTF-8。否则中文名称可能先变为乱码，再在下次启动时导致 JSON 解析失败。回归测试应使用实际的 Windows PowerShell 5.1，并同时核对解析成功与中文原值保留；只在新版 PowerShell 中通过不足以证明桌面入口正常。

本次修复的冷启动、重复打开、启动器退出和无新增报错验证记录位于 `tests/results/launcher-encoding-fix.json`。

## 后台仍在但桌面没有窗口

最后一个原生窗口关闭后，Bloc 的图形循环可能停止，而后台和模型客户端仍在。仅查询进程存活、`MainWindowHandle` 或把打开动作放进未运行的图形队列，都不能确认桌面已打开。

`src/runtime/open-desktop.mjs` 是桌面启动器使用的短时命令。GT 创建或复用主界面，发布实际 HWND。桌面启动器核对所属进程，等待窗口连续可见且未最小化，再记录 `logs/launcher-desktop.json`。Codex 和桌面分别报告就绪。

`tests/results/desktop-reopen.json` 记录真实快捷方式恢复测试。回执只表示记录当时的窗口状态；之后用户仍可关闭或最小化窗口，不应把旧回执当作当前可见状态。

## 常见核对方向

- 页面没有更新：区分活对象是否改变、窗口是否显示、方法是否仍在旧调用栈，以及状态是否已保存。
- 模型等待不返回：核对当前轮次回执、连接日志和工具活动。检查工具回调是否同步发起另一轮模型调用，以及本机文件邮箱是否被同步等待占住。
- 保存后没有恢复新内容：核对是否使用当前统一保存入口、对应检查点是否成功提交、下次启动加载了哪一代。
- 重启后线程改变：核对独立绑定与显式新建记录；不能静默另开线程来掩盖恢复错误。
- 环境退出而 Codex 仍存在：核对进程路径、所属实例和监管状态，不凭进程名结束其他会话。
- 关闭后弹出“找不到进程”：核对 `open-loom.ps1` 是否错误等待了整棵子进程树。启动器只应等 `start.ps1` 返回就绪，激活窗口后立即结束；关闭过程不再由启动器跟随。启动与激活之间已经关闭窗口也应安静返回。

排查需要调整实现时，先读 [运行环境的观察与演进](01-运行环境的观察与演进.md)；保存和结果不确定的边界见 [保存恢复与生命周期](03-保存恢复与生命周期.md)。

## 流式对话验证

tests/conversation-stream.st 使用隔离事件文件验证中文 UTF-8 跨读取边界、增量读取不重放、完成回复去重、进度与回答分离、摘要与原始 content 的边界、工具失败与结果、结构化字段隐藏及跨线程轮次隔离，不调用模型。结果为 tests/results/conversation-stream-tests.json。真实日志另与持久回执核对；原生控件的追加与选择保留、左右栏尺寸检查见 conversation-stream-ui.json。这些文件是当次验证依据。

现行 GT 客户端等待模型轮次完成、主动取消或连接故障。历史回执中的 `Codex turn timed out` 来自旧实现的轮次时限。排查时核对回执的 `startedAt`、`completedAt` 和原请求状态，再决定是否重试。

`tests/desktop/check-application-isolation.mjs --mock-codex` 用本地 App Server 测试替身保持一个待完成的轮次，然后验证独立管理通道发出的取消请求能结束该轮次。

## 原生紧凑对话验证

tests/native-conversation-ui.st 在 GT UI 队列执行，不调用模型。覆盖只读 Markdown、流式块复用、原始 Markdown 保留、未闭合代码围栏、代码不执行、表格空单元格与转义分隔符、工具详情与 Markdown 源码状态复用、中断结果未确认状态、真实消息投影、无变化条目不重绑、Enter 快捷键和实际事件阅读进程。结果见 tests/results/native-chat-validation.json。

原生布局与 Markdown 示例的渲染导出分别为 tests/results/native-chat-v2.png、native-markdown-sample.png。它们只记录导出时的状态。初始源码包括 conversation-components.st；磁盘语法及方法与活镜像一致性应另行核对，完成后提交检查点。
`tests/native-conversation-visual.st` 核对居中阅读宽度、内容收缩气泡、本地时间、输入提示、原生行高、矢量状态、活动条目排版和异常条目回退。它还检查活页面的列表已完成布局并存在可见行。结果为 `tests/results/native-chat-visual-validation.json`。源码语法与活镜像方法一致性的检查结果见 `native-chat-source-validation.json`。
