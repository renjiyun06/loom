# 文档编写与维护

## 结构与职责

`workspace` 只存放 AGENTS.md 与现行编号说明。AGENTS.md 中的环境必知说明直接维护，按需目录以编号文档的元数据为来源。详细事实在对应正文维护，不同时保留两份不同的现行说明。

编号文件采用 `NN-标题.md`，当前从 `00-` 到 `07-`，新增时选取未使用的两位编号。编号负责排序，不是文档身份；调整排序或名称时保留稳定的 `id` 并更新引用。不要因序号改变就使已有语义身份失效。

本目录保留 Loom 当前的说明与专题文档。退役环境、历史资料和一次性迁移脚本放在本项目根目录之外，不作为本环境的装载或运行依赖。

## 统一区块头

入口和现行编号文档开头使用以下四个 YAML 字段，不增加 `status`：

文件使用 UTF-8 编码，正文采用标准 Markdown。现行导航文件也使用同样的元数据；归档的历史原文保留原样，不作为现行规范。

```yaml
---
id: "runtime-evolution"
title: "运行环境的观察与演进"
summary: "说明如何检查活对象、方法和进程，并修改运行中的程序；维护运行行为时读取。"
updated: "2026-11-20T12:05:14+08:00"
---
```

- `id` 是稳定的英文标识，使用小写字母、数字和短横线，不能重复。
- `title` 与编号文件名中的标题、正文第一个一级标题一致。
- `summary` 是单行简介，既说明内容，也说明何时需要读取；简介用于选择文档，不能代替正文。
- `updated` 是最后一次实际修改的时间，必须保留日期、时、分、秒与时区。

时间统一使用 ISO 8601 格式 `YYYY-MM-DDTHH:mm:ss+08:00`，对应 Asia/Shanghai。例如 `2026-11-20T12:05:14+08:00`。使用真实更新时间，不只写日期，也不把文档重新读取算成一次更新。YAML 中将时间写为引号包裹的字符串。

需要核对当前上海时间时，可执行只读命令：

```powershell
([DateTimeOffset]::UtcNow.ToOffset([TimeSpan]::FromHours(8))).ToString('yyyy-MM-ddTHH:mm:sszzz')
```

## 修改与目录同步

1. 先检查实际实现和当前说明，确定本次应修改哪一份正文。
2. 修改正文后更新该文件的 `updated`，核对 `title` 和 `summary` 是否仍然准确。
3. 同步 AGENTS.md 中该项的标题、标识、简介、时间和正文链接，并更新 AGENTS.md 的更新时间。
4. 校验元数据、编号、稳定标识、内部链接及目录一致；不要让入口指向不存在或过期的现行正文。

具备相应文件写权限时，可运行下列命令更新时间并同步目录：

```powershell
& D:\Loom\runtime\node\node.exe D:\Loom\src\documentation\catalogue.mjs --touch "01-运行环境的观察与演进.md"
```

不带参数只同步目录，`--touch-all` 可用于有意更新全部现行说明时间的初始化或整批维护，不用于日常无改动刷新。工具只替换 AGENTS.md 的 `DOCUMENT-CATALOGUE:START` 与 `DOCUMENT-CATALOGUE:END` 之间的目录，不覆盖环境说明。

若当前 shell 只有读权限，可以通过已提供的 Glamorous Toolkit 文件能力修改相应文本，再手动同步区块头和目录；目录维护格式不依赖某一种写盘工具。随后执行只读校验：

```powershell
& D:\Loom\runtime\node\node.exe D:\Loom\src\documentation\catalogue.mjs --check
```

校验失败应先修正文档，不为让校验通过而删除必需的元数据或现行链接。

## 内容与演进

区分必须遵守的协作约定、当前实现、已经验证的事实和未来设想。实现变化后更新说明，不把早期目录、类名或存储方式写成阻止后续演进的永久规定。

入口加载不会证明所有正文已经读过。选择需要的文档并完整读取；上下文中只剩旧摘要、或者文档已更新时，重新读取相关正文。新增文档本身也不意味着旧会话已经重新装载了所有内容。
