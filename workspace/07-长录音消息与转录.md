# 长录音消息与转录

## 对话录音

在「织境对话」中，点击发送按钮旁的麦克风图标。录音条向左展开，依次是取消、左段波形、暂停或继续、右段波形和确认。两段波形连续显示同一份麦克风电平。暂停冻结波形并停止采集，继续时追加到同一份 WAV。

取消删除本次未发送的录音。确认结束录制并登记一条录音消息，立即显示可播放的原音，下面显示转录状态。背景转录结束后，文字出现在同一条消息的原音下方。转录失败或未识别到语音时显示对应状态，原音仍可播放。音频导入和转写也可通过后台接口使用。

录音采用 Windows WinMM 流式写入本地 WAV，不以实时听写会话维持录音，没有 60 秒短句限制。当前最长录音为五小时。发送后转换为 16kHz、16bit、单声道 FLAC，使用讯飞「录音文件转写大模型」。当前服务限制为五小时、上传文件至多 500MB，超限明确报错。

GT 持久化录音消息后，音频服务异步请求讯飞。只有转录成功且识别到文字，GT 才会调用 Codex。Codex 收到一条 `kind` 为 `audio` 的用户消息，`text` 是转录文字。原音保存在 Loom，供用户在界面回听与核对。

关闭对话标签会结束正在录制的音频并保留草稿。已发送的转录和模型处理继续由运行环境负责。退出整个运行环境会停止录音，重启后麦克风需由使用者重新开启。

## 所有内容的位置

所有内容都在 `D:\Loom` 内，不依赖 Mira 的全局语音配置。

| 位置 | 内容 |
| --- | --- |
| `config/xfyun.local.json` | 本地 VoicePad 应用的 `appId`、`apiKey`、`apiSecret`，已加入忽略规则，不在日志或文档输出实际值。 |
| `src/audio/AudioHost.cs`、`build.ps1` | Windows 录音、原音播放、原生文件选择器及构建入口。 |
| `runtime/audio/AudioHost.exe` | 编译后的本地录音与播放工具。 |
| `runtime/media/ffmpeg.exe`、`ffprobe.exe` | 本环境携带的预处理和音频时长检查程序。 |
| `src/audio/xfyun.mjs` | 文件转写请求、签名和转录结果解析。 |
| `src/audio/voice-service.mjs` | 音频消息、录音子进程、转写任务、持久化和恢复。 |
| `src/runtime/voice.st` | `LMVoice` 的业务实现，以及对对话程序的增量接入；界面在 `src/runtime/conversation-ui.st`。 |
| `state/audio/<音频ID>/original.*` | 原始音频，不因转录、播放或重启而替换。 |
| `state/audio/<音频ID>/message.json` | 音频状态、时长、原音名称、消息 ID、订单号、查询参数、识别文本和时间段。 |
| 同目录下的 `transcription.flac`、`preview.wav` | 发送和回放需要的派生文件。 |
| 同目录下的 `provider-result.json` | 最新一次讯飞订单查询结果，用于核对识别结果。 |
| `state/audio/index.json` | 供运行时读取的音频状态投影，不是唯一持久依据。 |
| `ipc/voice/requests`、`results` | 带稳定 UUID 的操作及回执。旧运行中没有回执的操作标记中断，不重新执行。 |
| `ipc/voice/meter.json` | 当前录音 ID、采集状态和最近的音量采样，用于原生双段波形。 |

录音数据不断写入磁盘，并更新 WAV 头。异常停止后保留已经写入的部分；极端损坏仍须核对文件，不能把“文件存在”当成录音完整。

状态投影只在内容变化时写入，录音时的已录时长按秒更新。Windows 文件切换期间的一次临时读取失败使用上一份完整投影，下次刷新继续读取，不弹出调试器；`LMVoiceLastReadError` 可用于诊断，成功读取会清除它。

## 转录状态与恢复

正常路径为 `draft → queued → preparing → uploading → processing → completed`。发送时，原生消息先持久化其 `audioId`，桥接依据该消息登记或恢复转录队列。后台完成转录后唤醒 Glamorous Toolkit 对话循环，沿用对话程序选定的 Loom 会话。等待中的录音和没有识别结果的录音留在界面，其他已就绪的消息仍可处理。

- 准备音频时中断：可以重新生成派生文件。
- 已有订单号：重启继续查询同一订单，不重新上传。
- 上传中断且没有订单号：标记 `unknown`，不得自动重传或用重试按钮重传；先在讯飞控制台核对订单。
- 查询暂时失败：保留订单与参数，稍后继续查询。
- 权限、额度或音频问题：保留明确错误；排除问题后通过后台 `retry` 继续，已有订单优先续查。
- 正常退出收束录音和播放；异常结束由 Windows Job 关闭本地子进程，重启只恢复资料和转录任务，不恢复麦克风录音。

## Glamorous Toolkit 内的调用和演进

```smalltalk
LMVoice index
```

```smalltalk
LMVoice job: '实际音频ID'
```

```smalltalk
LMVoice request: 'play'
    options: (Dictionary new at: 'audioId' put: '实际音频ID'; yourself)
```

`request:options:` 返回操作 ID；`LMVoice await:` 等待相应回执。录音、文件选择等耗时操作应放在独立 Process，避免阻塞 UI 和通信邮箱。录音相关动作是 `record`、`pause`、`resume`、`stop` 和 `cancel`。`pause`、`resume` 和 `cancel` 接收 `audioId`。其他动作包括 `pick`、`import`（绝对 `file` 路径）、`play`、`stop-playback`、`retry`、`submit` 和 `close-window`。

`LoomConversation submitAudio:text:` 持久登记录音消息。重复提交同一录音时复用消息 ID。`LMConversation nextInput` 读取已完成的转录，向调用方提供带录音标记的文本消息。输入栏的 `LMVoiceComposer` 负责录音和确认，消息列表显示原音播放器和转录结果。旧镜像恢复时以磁盘上的订单状态为准。

运行环境中的 Codex 可以继续检查、演进这些类和文件，并按统一保存流程保留改动。修改 Node 桥接或本地音频工具后需要有序重启运行环境；只修改 Glamorous Toolkit 方法通常可热生效，仍需核对已进入的旧调用栈。

## 已执行的验证与参考

已经做过真实麦克风约 65 秒录音、原生按钮录制与停止、音频导入、原音播放、真实讯飞转录、订单重启续查、原音重启后播放，以及向原 Codex 会话提交转录并取得回复。故障测试另覆盖未知上传不重传、临时查询失败及中断后不重启麦克风。

当前自动化检查使用 `tests/voice-recovery.test.mjs` 和 `tests/loom-runtime.test.mjs`，覆盖转录恢复、本地音频和持久会话绑定。调用设备、真实服务或模型的检查应明确执行，不当作无副作用的只读检查。

服务契约以[讯飞录音文件转写大模型官方文档](https://www.xfyun.cn/doc/spark/asr_llm/Ifasr_llm.html)为准；协议、配额、凭据和当前运行结果须实际核对。
