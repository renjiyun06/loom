# 业务程序执行与子请求

## 调用约定

Codex 通过 `runtime_eval` 中的 `loomRun` 启动可能调用会话的 Loom 业务程序。每个会话在当前轮次内一次推进一条业务历程。不同会话可以同时保留活动轮次。同一次执行可以产生零个、一个或多个顺序的子请求。运行时保留业务进程和调用帧，普通 Smalltalk 方法继续按调用栈运行。

启动和接续都先检查工具回显的 `ok`。成功时，`value.kind` 有以下两种取值。

| kind | 含义和下一步 |
| --- | --- |
| `completed` | 本次历程完成。`executionId` 标识这次执行。可序列化的结果放在 `value`，包括显式的 `nil`（JSON 的 `null`）。其他活对象以 `valueClass` 描述。当前轮次可用 `loomRun result` 取回原对象，直到下一次启动。 |
| `subrequest` | 这一次工具调用已经返回，业务历程仍在等答复。`requestId` 标识具体问题，`selector` 是原消息名，`originExecutionId` 是发问程序的执行编号。读取原始请求，交回答案并检查下一次工具结果。 |

例如，分别在三次工具调用中执行下列代码。假设当前会话是 `main`。将示例中的编号替换为实际返回的 `requestId`。

```smalltalk
loomRun start: [ (LoomCodex session: #main) review: '支付回调重跑通过' ]
```

```smalltalk
| request |
request := loomRun request: '返回的编号'.
{ request message selector asString. request message arguments first. request caller method selector asString }
```

```smalltalk
loomRun answer: '返回的编号' with: '通过'
```

答复会唤醒发问程序，并等到当前历程完成或出现下一次子请求。检查结果后再采取下一步。启动只做一次。处理子请求时，原始消息和发问处调用帧分别从 `(loomRun request: id) message` 和 `(loomRun request: id) caller` 取得。外层的 `loomMessage` 和 `loomCaller` 仍指向本轮最初的对象调用。普通程序如 `loomRun start: [ nil ]` 第一次就完成。程序出错按工具错误返回。对象业务入口最后仍用 `loomReturn value:` 提交最外层调用方需要的对象。它与给子请求提交答案是两个返回点。日常反射可直接用 `runtime_eval`。从工具回调启动业务逻辑时使用上述入口，由 Loom 分配独立业务 Process。

## 谁提问、谁答复、谁继续

例如 S 的程序 A 调用会话 T，T 的程序 Q 又向 S 提问。A 通过普通 Smalltalk 对象消息或 `ask:` 调 T，运行时将 A 的执行编号关联到 T 的轮次。T 用 `loomRun start:` 启动 Q。Q 可以通过 `(LoomCodex session: #S) targetVersionFor: release` 提问。

1. Loom 从 Q 沿父执行找到 S 正在等待的 A，保留消息、真实实参、调用帧及 Q 的等待点，用 A 的工具返回交付子请求。T 仍在等 Q 的结果。
2. S 读取 `loomRun request:` 并按编号答复。答案送回 Q 的等待点。S 的接续调用继续等待 A。
3. Q 执行完，T 收到 Q 的 `completed`，按原业务约定向 A 交回核查结论。A 执行完，S 才收到 A 的 `completed`。

目标会话在本条链上时，子请求沿这条链找到它。对其他会话的调用沿用其原来的入口和会话锁。无关历程在目标会话排队。每个请求只能由持有它的轮次答复一次。一个会话可以直接回答当前子请求，继续该历程期间，第二次独立启动会被拒绝。

## 如何查看记录

业务历程用 `executionId` 关联启动与完成。子请求用 `requestId` 关联发问与答复。跨会话的子历程还会记录 `parentExecutionId`。发问、答复活动里的 `toolCallId` 关联承载该步骤的实际工具调用。轮次另有协议编号。活动记录与现有会话活动存放在同一处，详情见[对话程序与调用机制](02-对话程序与调用机制.md)。执行中的活对象和等待点保存在当前 GT 镜像中。本协议覆盖正常运行和进程内接续。跨崩溃的子请求接管另行设计。
