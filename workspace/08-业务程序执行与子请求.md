# 业务程序执行与子请求

## 调用约定

将 Smalltalk 源码直接交给 `runtime_eval`。GT 为每次求值分配执行编号和受管进程，观察调用栈、运行计算、将对象转成工具结果和求出子请求的答案都在该机制内进行。同一轮次串行推进，不同会话可以同时活动。普通 Smalltalk 方法继续按原有调用栈运行。

先检查工具回显的 `ok`。成功时读取顶层 `kind`，它有以下两种取值。

| kind | 含义和下一步 |
| --- | --- |
| `completed` | `executionId` 标识已完成的执行。可序列化的结果放在 `value`，包括显式的 `nil`（JSON 的 `null`）。其他活对象以 `valueClass` 描述。下一次求值可用 `loomRun result` 取得最近成功完成的外层执行的原对象。 |
| `subrequest` | 这一次工具调用已经返回，业务历程仍在等答复。`requestId` 标识具体问题，`selector` 是原消息名，`originExecutionId` 是发问程序的执行编号。读取原始请求，交回答案并检查下一次工具结果。 |

例如，分别在三次工具调用中执行下列代码。假设当前会话是 `main`。将示例中的编号替换为实际返回的 `requestId`。

```smalltalk
(LoomCodex session: #main) review: '支付回调重跑通过'
```

```smalltalk
| request |
request := loomRun request: '返回的编号'.
{ request message selector asString. request message arguments first. request caller method selector asString }
```

```smalltalk
loomRun answer: '返回的编号' with: '通过'
```

把 `loomRun answer:with:` 作为这段答复代码的最后一步。求值成功后，运行时将答案送到原等待点，并回显原执行的下一次提问或完成结果。答复代码本身也可以查询对象、调用会话。如果它又收到子请求，先答复这个内层问题。如果答复代码出错，工具回显 `ok: false` 和错误，原问题仍可重新答复。

处理子请求时，`request message` 和 `request caller` 给出发问处的原始消息和调用帧。`loomMessage` 和 `loomCaller` 仍指向本轮最初的对象调用。所有子请求处理完后，用 `loomReturn value:` 将实际对象交回最外层调用方。

## 谁提问、谁答复、谁继续

例如 S 的程序 A 调用会话 T，T 的程序 Q 又向 S 提问。A 通过普通 Smalltalk 对象消息或 `ask:` 调 T，运行时将 A 的执行编号关联到 T 的轮次。T 直接在 `runtime_eval` 中运行 Q。Q 可以通过 `(LoomCodex session: #S) targetVersionFor: release` 提问。

1. Loom 从 Q 沿父执行找到 S 正在等待的 A，保留消息、真实实参、调用帧及 Q 的等待点，用 A 的工具返回交付子请求。T 仍在等 Q 的结果。
2. S 读取 `loomRun request:` 并按编号答复。答案送回 Q 的等待点。S 的接续调用继续等待 A。
3. Q 执行完，T 收到 Q 的 `completed`，按原业务约定向 A 交回核查结论。A 执行完，S 才收到 A 的 `completed`。

答复代码继承发问者的调用链。例如 A 调 B、B 调 C、C 回问 A，此时 A 计算答案时也可以询问正在等待的 B。各层用各自的请求编号答复，答案返回各自的等待点。对链外会话的调用使用该会话的模型入口。无关历程在目标会话排队。

## 如何查看记录

在对话侧栏或「运行活动」中，每次受管求值占一行。标题显示操作名称，例如「执行 Smalltalk」。右侧显示工具名和「执行中」，成功后「执行中」换为以秒计的实际耗时。等待答复时显示问题，失败时显示错误。点击这一行，默认打开「过程」，可查看返回值摘要、提问和答复，以及执行和问题编号。成功保存的检查点可按编号核对。「参数」和「结果」保留对应工具调用的原始详情。历史记录中没有保存的问题或答案只显示已知信息。

业务历程用 `executionId` 关联启动与完成。子请求用 `requestId` 关联发问与答复。跨会话的子历程还会记录 `parentExecutionId`。发问、答复活动里的 `toolCallId` 关联承载该步骤的实际工具调用。轮次另有协议编号。活动记录与现有会话活动存放在同一处，详情见[对话程序与调用机制](02-对话程序与调用机制.md)。执行中的活对象和等待点保存在当前 GT 镜像中。本协议覆盖正常运行和进程内接续。跨崩溃的子请求接管另行设计。
