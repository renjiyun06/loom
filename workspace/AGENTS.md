# 织境运行环境入口

## 适用范围

这份说明面向 Loom 调用的每一个 Codex 会话。所有会话在启动或恢复时都使用 `D:\Loom\workspace` 作为工作目录，从这里读取同一份 `AGENTS.md` 和专题文档。每次调用的任务和工作位置由发起调用的程序及其运行现场决定。

## Loom 是什么

织境（Loom）是一套让程序在运行中调用 Codex、并能在使用者授权下由 Codex 演进的系统。Glamorous Toolkit（GT）承载活对象、业务状态和程序流程，Node 桥接把调用及结果送到对应的 Codex 会话。程序决定何时调用、传入哪些对象，以及拿到结果后继续执行什么。

业务状态由 Loom 的程序和持久数据承载。Codex 可以在调用中观察真实对象、源码和执行现场。主会话也可以在任务授权范围内演进 Loom 的业务程序，改动以活镜像中的实际行为和保存回执为准。

## Loom 会话与本次调用

每条 Loom 会话都有持久标识，程序通过 `LoomCodex session: #标识` 明确选择。每条 Loom 会话可以按时间先后接续多条底层 Codex 会话。重启沿用当前绑定，明确切换底层会话后仍使用原来的 Loom 标识和业务状态。

这份文件只定义共用约定。发起调用时，程序选择 Loom 会话，桥接在调用现场提供 `loomSessionId`。收到「Loom 调用了你。」后，先用 `runtime_eval` 读取该标识，确认本次调用的会话身份。再通过 `loomInvocation` 查看方法名 `selector`、调用处源码 `markedCallerSource` 和实际入参 `arguments`，按现场要求完成任务，并用 `loomInvocation return: anObject` 交回结果。

## 用户交互与系统修改

任何会话都可以通过 Loom 程序为它提供的入口与使用者沟通。交互方式和返回值由发起调用的程序决定。

只有运行时身份为 `main` 的会话可以修改决定 Loom 系统行为的代码，包括活镜像中的业务程序和承载这些行为的磁盘源码。其他会话照常执行业务、操作任务数据和交付结果。需要调整 Loom 行为时，由 `main` 实施。

## 运行时工具

`runtime_eval` 接受一个参数 `code`，值为在当前活镜像内求值的 Smalltalk 源码字符串。它能读写活对象和方法，回显返回可转换为 JSON 的值。对象调用中会绑定 `loomInvocation` 和 `loomSessionId`，后者是当前命名会话的字符串。工具细节和运行时注意事项见 [工具技能与能力发现](04-工具技能与能力发现.md) 与 [运行环境的观察与演进](01-运行环境的观察与演进.md)。Smalltalk 和 GT 的通用用法可自行查阅上游文档。

按下面的摘要选择与当前任务相关的专题，再读正文。维护 Loom 的磁盘源码位于 `D:\Loom\src`。更新专题时，按文档维护指南同步摘要和修订时间。
